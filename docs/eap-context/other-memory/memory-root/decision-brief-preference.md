Jeff's feedback (2026-07-10, trailer project; he says he gives this feedback "often across several projects"): decision asks were "too dense" and over-escalated.

**Why:** he's doubtful "every question that comes my way is really so ambiguously divorced from the objectives" — most escalations are answerable from the recorded philosophy/objectives, and dense prose hides the actual stakes.

**How to apply:** (1) TRIAGE before escalating: attempt to answer each question from the project's recorded objectives/philosophy/interview record; only escalate items where a real objective conflict or genuinely-unknowable owner preference remains, and state WHICH objective fails to decide it. Self-decided items go in an FYI-with-veto table, not questions. (2) FORMAT the remaining real decisions as a table — one row per decision: options, concrete implications of each option, recommendation + default — visually broken up, answerable with one word per row. He suggested making this a reusable skill or CLAUDE.md entry. (3) ESCALATION STYLE (owner, 2026-07-15, verbatim: "don't hang on me for clear direction! Surface ambiguities using socratic questions."): never park work awaiting direction that's derivable from recorded objectives — proceed on the default and note it. When a GENUINE ambiguity must reach him, frame it as a socratic question that exposes the underlying tension and forces a decidable choice (the 2026-07-09 interview style: "if serving X means disappointing Y, which wins and why?"), optionally with the option/implication table as supporting detail — the question leads, the table supports.
