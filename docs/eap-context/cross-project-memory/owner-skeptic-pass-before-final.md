Owner addendum relayed 2026-07-20 (verbatim): "Any of those sourcing rounds that think they might be final, have some skeptical agents poke at them."

**Why:** the owner wants finality to be earned and evidenced, not self-declared. A round that "feels done" is exactly where a wrong donor cross, a missed candidate, an over-claimed coverage number, or a now-stale live listing hides — an independent adversarial pass at the finality boundary catches what the authoring pass rationalized past.

**How to apply:**
- Whenever a sourcing round (a case file, a family survey, a ledger bucket, the pigtail workstream, any round you're about to call complete) is ABOUT TO BE marked final / flipped ready, FIRST run a dedicated **skeptical-agent pass**: independent skeptic agents whose job is to BREAK the round's claims — refute donor/sibling crosses (way-count/family/keying, not just "same family"), surface missed candidates, challenge over-claimed coverage/counts, and re-check that cited live listings/prices/URLs are still valid (not stale).
- **Bake the skeptic verdicts INTO the case files / ledger** (a skeptic-review section, per-claim survived/refuted/downgraded, with evidence) so finality is documented in-artifact — not just asserted in a PR body or chat. Downgrade or fix anything the skeptics break before declaring final.
- This is IN ADDITION to the refute-by-default verification done during authoring — it's a distinct, independent pass at the finality boundary, run by agents that did not author the round.
- Applies to new rounds AND to any existing round being reconsidered as complete (e.g. coverage-ledger buckets marked done). The project's `skeptical-review` skill / adversarial-check agents are the machinery.
