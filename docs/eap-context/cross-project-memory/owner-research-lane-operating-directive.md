Owner directive relayed 2026-07-20 (verbatim excerpts): "Open PRs and surface questions as github comments with clear questions and context for impact. I don't want to see questions about 'oh this is very much the same, but it's a slightly different shape.. what to do?!' If an agent is uncertain, do an adversarial agent debate grounded in our current source of truth. A 'should I proceed?' isn't a real decision that should be gated on me. If you're not sure _how_ to proceed because there are competing interests, that's the sort of thing to surface. Use adversarial check agents as you go... My goal is to enable you to make AS MUCH PROGRESS as possible."

**Why:** the owner is optimizing for maximum autonomous throughput across the parallel EV1 sourcing/harness/hardware lanes. Proceed-permission gating and low-stakes shape-mismatch questions waste his round-trips; he wants agents to self-resolve ordinary judgment calls with evidence, not defer.

**How to apply:**
- NEVER ask "should I proceed?" — proceed. Land work as PRs (draft→ready per the repo's ready-immediately rule).
- Ordinary uncertainty — including sibling-vs-not / donor-match / "same family but slightly different shape" calls — resolves via **adversarial agent debate grounded in the catalog + manual sources** (redux R4 truth, the sourcing case files), NOT by asking the owner. Use adversarial/skeptical check agents as you go (refute-by-default verification before asserting a "confirmed" cross).
- Surface to the owner ONLY a genuine **competing-interests fork** — where two legitimate goals conflict (e.g. fidelity vs cost, faithfulness vs road-legality) and the tradeoff is his to make. Even then, surface it as a **GitHub PR comment** with clear question + impact context, not a blocking gate.
- Applies to all research lanes: harness pigtail/segment sourcing, odds-and-ends hardware, sibling-ID sweeps, and future ones.
