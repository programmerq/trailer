P (state-machine modeling + PChecker) formal-methods workstream for electricsim, owner-validated 2026-07-10.

**Where it lives:** ONE consolidated P project `formal/p/ev1/` (PSrc/<module>/ machines + Modules.p; PSpec monitors; PTst incl. cross_module_tests.p). Earlier PR #211 (charger/PIM) MERGED to main 2026-07-15; run_sweep.sh nightly + gen_p_composition_map audit on main. P↔C maps in `docs/formal_p_state_map.md`; rules in `docs/proposals/formal_methods_p_2026-07-09.md`. `formal/p/` is off the CI gate by design. Run: `cd formal/p/ev1 && p compile && p check -tc <tc> -s <n>`; sweep `bash run_sweep.sh`.

**Modules modeled:** charger, ad, rsa, btcm, bpm, pim, apm, sdm, hv_coordination, lhjb, rhjb, tjb, brake_lamp_chain, pscm, htcm, ipc (scan_tool skipped). Analog plants NOT modeled — but sensor VALIDITY/fault modes + brownout ARE, as discrete hysteresis machines.

**Discipline (owner-mandated):** claude[bot] reviewer is disabled, so every push is gated by an internal adversarial self-review agent (told to REFUTE — re-runs `p check`/`make test`/audits, verifies manual readings vs redux scans). `p check` is randomized bounded exploration, NOT a soundness proof — language stays "explored N schedules, 0 bugs", never "proven correct". **Toolchain: the P toolchain is NOT persistent across these remote sessions — install it fresh each session via `curl -fsSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 8.0` (installs .NET 8 SDK to `/root/.dotnet`) then `/root/.dotnet/dotnet tool install --global P` (P v3.1.0.0 → `/root/.dotnet/tools`); then `export PATH="/root/.dotnet:/root/.dotnet/tools:$PATH"; export DOTNET_ROOT=/root/.dotnet`.** Baseline `p compile` ~7s; a 2000-schedule tcBTCM check ~49s; the full 18-tc sweep at 10k is on the order of hours.

**LESSON — direction of truth (owner, 2026-07-19):** re #337's 'policy realign': the owner challenged that the P session was treating the C code as settled truth ('the P model should have been able to catch the incorrect implementation in C in the first place'). Standing norm: the P model encodes what the EV1 SHOULD do per the manuals/DTC catalog/patents; the C is the artifact under test. Every model-vs-C divergence gets adjudicated against the authoritative sources with three verdicts: (a) manual says C right → model change stands, cite page; (b) manual says old model right → the C is the bug — file it, revert the model change so p check catches the defect, route the C fix; (c) manual silent → @inferred with reasoning. 'The C is newer' is never evidence of correctness. A C-favoring re-model that silences a monitor is exactly the failure mode this norm exists to prevent.
