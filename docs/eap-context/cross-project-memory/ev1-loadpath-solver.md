**Built 2026-07-20** (owner-directed major build session). A from-scratch C++17 matrix structural-analysis (direct-stiffness) solver that computes load paths through the EV1 aluminum spaceframe — the tool to verify a proposed spaceframe design carries load faithfully. Home: `programmerq/ev1` umbrella repo, top-level `loadpath/` (decision: `decisions/2026-07-20-loadpath-home.md`). Branch `claude/loadpath-solver`, PR #22 (https://github.com/programmerq/ev1/pull/22).

**What it is:** 3D 2-node Euler-Bernoulli beam element (12-DOF, optional Timoshenko shear), direct-stiffness assembly, dependency-free dense LDLᵀ solver, BC partitioning, reactions + per-member axial/shear/moment recovery (the load-path payload). Standard C++ only, NO external solver dependency. Units contract N/mm/MPa/rad. CLI: `loadpath <model.yaml> --case bending|torsion|point --out <prefix>` → text + JSON + self-contained HTML (frame viz colored by load path). Input = commented free-YAML (nodes/sections/materials/members/supports/loads), parsed by a hand-rolled `yaml_lite.hpp`.

**Datum:** node coords use redux master `frame-underbody-xyz` (body-149): X fore/aft +rear (O-plane 1999mm fwd of front master gauge hole), Y +right, Z +up (0 = 309mm below rocker lower flange), mm, ±1mm tolerance. So real EV1 geometry drops in via the datum lattice (`ev1-manual-redux/geometry/data/*.yaml` datum ids `datum-bNNN-N`); redux-ref node resolution is a documented TODO (inline coords today). The mass-properties session shares this exact datum for CG stations.

**Alloys** (`loadpath/data/alloys.yaml`, all `@inferred 2026-07-20`, external-cited — the EV1 manuals print ZERO mechanical properties): A356-T6 (E 72400 MPa, ν 0.33, yield 205), 6063-T6 (E 68000, yield 214), 5754-O (E 68000, yield 90). **C210-T6 has NO findable authoritative source** → ships as a documented **A356-T6 proxy at confidence:low** (corroborated by the EV1-era GM Precept spaceframe, which used A356-T6 castings). Do not treat C210 numbers as measured.

**Validation is the product** (`loadpath/docs/validation.md`): 15/15 closed-form tests green (cantilever PL³/3EI both bending planes, ML/EI, PL/EA, TL/GJ twist, propped cantilever, portal sidesway, equilibrium gate). Cross-checked vs **PyNiteFEA 3.0.0** as an independent oracle (never linked): agree to max rel-diff 7.3e-12, reactions ~1e-15. Formulation spec was adversarially reviewed before coding (caught 6 errors incl. a Gram-Schmidt-vs-cross-product triad bug that swaps Iy/Iz on non-symmetric sections); finished code audited term-by-term (signs/DOF/units) — clean.

**Honest limitations (in the README):** v0 joints are rigid/simple-spring — bonded/riveted aluminum joint compliance is the real hard part + dominant uncertainty, member-end model built to be upgraded (aircraft/bonded-joint stiffness practice from the spaceframe session's WS2 slots in later). The tool **informs + checks faithfulness; it does NOT certify** — the program's paid outside-engineering review stays the gate.

## Joint-model upgrade + scenario/crash load cases (2026-07-20/21, PR #22, owner-greenlit at ultracode scale)

All landed on the SAME rolling PR #22 (branch `claude/loadpath-solver`), ready-for-owner-click, NOT merged (per [[ev1-merge-waves-discontinued]]). Latest head at hand-off: `605761b`. Full arc: base solver → images → bonded-joint literature review → scenario/crash load cases → v1 joint springs → v2 joint library → payoff quantification + graphs → validation.

**Scenario/crash load cases** (`scenario_cases.hpp`, `mass_model.hpp`): a tonne-unit mass model (lumped point masses in kg→tonne + structural self-weight; g0=9810 mm/s²) drives inertial g-cases (accel/brake/corner/bump) plus two crash ANALOGS — `frontal` (equivalent-static ~30 g longitudinal, reacted at the FRONT barrier so front rails are the load path — deliberately not the rear) and `roofcrush` (FMVSS 216a quasi-static platen at exact 5° pitch/25° roll, SWR default 3.0). Honesty banner: accel/brake/corner/bump are faithful equivalent-static; frontal is elastic-load-path-only (no plasticity/crush); roofcrush's load path is meaningful but true crush strength isn't. Real-world basis cited: EV1's one documented test = 35 mph frontal NCAP; ~290 lb aluminum spaceframe; centerline "T" pack shielded from frontal crush; EV1-era roof std was SWR 1.5 (no published EV1 roof result — 3.0 is a modern-analog target). CLI: `--case accel|brake|corner|bump|frontal|roofcrush`, `--g`, `--swr`.

**v1 joint springs** (`joint.hpp`, `joint_condensation.hpp`): 6-DOF linear member-end springs on the `Member` seam. v1 sprung DOFs = axial ka + torsion krx (series) + two bending rotations kry/krz (Monforton-Wu semi-rigid 4×4); shear held rigid. Rigid limit is BYTE-IDENTICAL by construction (absent spring = base matrix, NOT a huge finite rate), so pre-existing tests are unaffected — verified bit-for-bit. Default joint class `weld_bond` = adhesive (Volkersen/Goland-Reissner) IN PARALLEL with fastener flexibility (Huth), grounded in SAE 960165 (the EV1 is weld-bonded, see [[ev1-spaceframe-avt-reframing-and-dossier]]). Formulation was adversarially locked (spec in scratchpad joint_spring_spec.md); 6 rate corrections applied; every rate tagged source-derived vs COUPON-TEST-REQUIRED. CLI `--joints rigid|weld_bond`.

**v2 joint library** (`data/joints.yaml`, `joint_library.hpp`): provenance-tagged classes (rigid, weld_bond, adhesive_only, spot_weld_only, rivet_only); per-DOF rates carry value/units/provenance/confidence/`coupon_test_required`, honest null where only a physical coupon can pin it. Data-driven class→rates resolution with the built-in as fallback.

**Payoff (headline)** (`docs/joint_stiffness_payoff.md`, `reports/joint_payoff*.svg/json`): rigid→weld_bond softening on the generic 2-door (PLACEHOLDER rates, NOT an EV1 result) — bending 338.7→271.8 N/mm (19.7%), torsion 16.2%, accel 17.7%, frontal 17.4%, roofcrush 18.5%. A joint-rate sensitivity sweep bridges honestly to the literature's 60-70% over-stiffness band (Chang 1974; Kho & Beevers 2001 +30 vs +22): at soft/coupon-realistic rates bending softening reaches ~70% (upper edge) / torsion ~63% (mid-band), and rigid is the λ→∞ stiff-joint limit (softening→0). Reproduces the literature MECHANISM; exact EV1 magnitude awaits coupon-calibrated rates. Informs-not-certifies throughout.

**Validation:** independent closed-form oracle to 4.3e-16; rigid-limit byte-identity confirmed; adversarial audits of condensation math + rates/library CLEAN; honesty critic caught + fixed one wording nit. 22/22 tests green.
