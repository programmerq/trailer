**PR #72 MERGED to main 2026-07-20** (merge-commit `6b6e4deb8a1a992a576cf14c689a96cb054266c1`), branch `adr/permissionless-capture`. Adds the decision record `docs/decision-records/2026-07-16-permissionless-screen-capture.md` (first under [[trailer-decision-records-date-slug-scheme]]; thresholds GPSC.1–GPSC.4) AND its implementation.

**Problem (owner dogfood):** the "Screen Recording" TCC prompt fires on first still-capture because macOS attributes the grant to the calling app, not to `screencapture` (Trailer already shells out to `screencapture -i`). On-device: crosshair UI is permission-free; TCC gates only pixel readback; Deny was indistinguishable from cancel → silent dead-end.

**Shipped:** a `capture_backend` setting (string in `[general]`, `RestartRequired`) **defaulting to `screencapture`** — runtime behavior unchanged until opted-in + validated. `src/platform/ScreenCaptureBackend.{h,cpp}` (pure `effectiveCaptureBackend()` selector, unit-tested off-Mac in `tests/test_capture_backend.cpp`), `src/platform/MacScreenCapture.mm` (Apple-only: `SCContentSharingPicker` → `SCScreenshotManager.captureImageWithFilter:configuration:completionHandler:` → PNG; bounded main-thread run-loop w/ 120s timeout, main-thread guard, main-queue-hopped callbacks; uses `picker.defaultConfiguration`, NOT `picker.configuration` which doesn't exist), `MacScreenCapture_stub.cpp` (non-Apple → Unavailable). By merge time, main's PR #86 had unified the two capture entry points into `Application::captureScreenshot(ShotMode, QWidget*)` AND dropped the stills pre-permission explainer (the exact knock-on the ADR predicted) — so the picker is folded in as ONE gated branch there: picker when configured+available+not-Region; **Region and any picker Unavailable/Failed fall back to `screencapture`** (the system picker selects a window/display, not a freeform rectangle); picker cancel is a silent no-op. Verified 72/72 tests green on Linux (stub path) before merge.

**On-device verification harness (also shipped, `tools/macos-capture-smoketest/`):** one-command local harness the owner runs — `tccutil reset ScreenCapture io.github.programmerq.trailer` → drive/prompt a picker capture → assert no `kTCCServiceScreenCapture` grant was created in the system TCC.db (needs Full Disk Access on Terminal; degrades to `CGPreflightScreenCaptureAccess` diagnostic + visual confirm) + preflight. Persistent-Mac / `tart`-VM CI matrix (14.0/14.4/15.x, Developer-ID-signed) noted as DEFERRED follow-up.

**STILL OPEN (follow-ups):** (1) the owner's on-device **GPSC.2 smoke test** must confirm the picker path is prompt-free before anyone flips `capture_backend` default to `screencapturekit` — the `.mm` compiled clean on his Mac (after the defaultConfiguration fix) but the no-prompt behavior across 14.0/14.4/15.x is not yet asserted; (2) build the deferred `tart`/persistent-runner CI if the owner commits the hardware; (3) reliability caveat: prompt-free picker behavior only moderately reliable before macOS 14.4 (+ first-Sonoma-beta FB12331920) — raise the `@available` floor to 14.4 if the smoke test shows 14.0–14.3 differ.
