Owner did ~20 min hands-on macOS dev-build testing 2026-07-16 and found 7 UX bugs the review machinery never caught (blurry HiDPI at default zoom, non-1:1 window sizing, File-menu "New" IA confusion, New/acquire actions vanish when a doc window is open, no zoom indicator, verbose permission dialog, ⌘N not mapped to new-from-clipboard). He asked whether the "annoyed user"/"UX expert" personas could have seen these and what would be better.

**Diagnosis (3 failure classes, evidence-based):** (a) ENVIRONMENT FIDELITY — offscreen QWidget::grab() runs at dpr=1, so the HiDPI/Retina class (#1) is structurally invisible; that's the [[gui-verification-capabilities]] backlog item's territory (docs/backlog/2026-07-15-gui-verification-capabilities.md), not re-solved here. (b) MODE OF REVIEW — personas read a diff + one static screenshot; nobody EXECUTES a task end-to-end with a goal, so 5 of 7 (flow/interaction bugs) are out of reach. (c) MISSING COMPARATIVE BASELINE — no persona compares against Preview/Acrobat. PR #64 is the sharpest evidence: it ran the SAME two lenses the owner used by hand, offscreen via grab(), and caught a disjoint narrower set — lenses fine, substrate was the ceiling.
