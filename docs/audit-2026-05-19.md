Four read-only audits run against the codebase at this branch's
HEAD (`claude/gallant-yonath-da121c`, parented on `main` at
`37bb4cb`). Each lens was prompted to find what someone in that
chair would care about, and to flag both what's wrong and what's
right — confirming the durability contract holds where it does is
as useful as finding a gap where it doesn't.

The four lenses were:

1. **Privacy / network surface** — does the code match
   PHILOSOPHY's "no telemetry, one outbound call" claim?
2. **Cross-platform consistency** — does the code assume Apple
   Silicon, the maintainer's home machine, or some other narrow
   target?
3. **Accessibility** — keyboard nav, screen-reader hooks, focus
   order, colour-only signals.
4. **Failure-mode / robustness** — does the code crash on
   plausible bad input? Does it silently lose data? Does it
   popup when it shouldn't?

Each section below is the audit's headline plus the findings it
yielded. The closing **Action register** at the end groups the
actionable items by where they should land (PHILOSOPHY change,
CONVENTIONS recipe, TODO follow-up, etc.).

## 1. Privacy / network surface

**Headline.** *Zero critical findings.* The PHILOSOPHY claim that
Trailer makes exactly one outbound call — ONNX model downloads via
`ModelDownloader`, gated on explicit user consent — is accurate as
of this audit. There is no telemetry SDK in the dependency graph,
no crash uploader, no clipboard-sniffing path that touches the
network, and no `qDebug` / log path that escapes the local disk.

### Confirmed-safe positives

- **`ModelDownloader` uses HTTPS-only with system cert validation**
  (`src/ml/ModelDownloader.cpp:43`). `NoLessSafeRedirectPolicy` is
  set; `ignoreSslErrors()` is not called anywhere in the tree.
- **Consent flow is explicit and persistent**
  (`src/ui/ModelManagerDialog.cpp:307`). URL and size shown before
  download; consent recorded as `ml_never_download_<id>` keys in
  `[first_use]`.
- **Download is cancellable mid-flight.**
  `ModelDownloader::cancel()` calls `QNetworkReply::abort()`.
- **No SaaS telemetry libs.** Zero matches for Sentry, Bugsnag,
  Mixpanel, Amplitude, or Rollbar in the source tree.
- **No `QProcess` invocations that leak document content.** All
  `exec()` calls are Qt event-loop methods, not shell-outs.
- **macOS share-sheet only passes a file URL** to NSSharingService;
  Trailer constructs nothing.
- **OCR clipboard writes are plain text only**
  (`OcrResultsDialog`).
- **ONNX Runtime, qpdf, toml++ make no runtime network calls.**

### Worth a closer look

- **P-WC-1: No CMake / clang-tidy lint preventing future
  `QNetworkAccessManager` additions.** `ModelDownloader.cpp` is the
  one legitimate caller today; nothing in the build catches a
  future contributor adding a second QNAM in, say, `MainWindow.cpp`
  without review. The privacy contract is enforced by code review,
  not by tooling. *Severity: Moderate — protective gap, not a
  current violation.*

- **P-WC-2: `ModelRegistry::setManifestForTesting()` is reachable
  from production code paths** (`src/ml/ModelRegistry.h:89`). Test
  isolation is correct today, but there's no compile-time guard
  preventing a misguided refactor from leaving a test-mode URL
  override active in a release build. *Severity: Minor —
  theoretical, no observed misuse.*

## 2. Cross-platform consistency

**Headline.** *Strong cross-platform discipline.* Path routing
goes through `AppPaths` / `QStandardPaths`; platform-specific
features (share sheet, no-window menu bar) use the
`Foo.mm` + `Foo_stub.cpp` separation with `isAvailable()` gating;
HiDPI / DPR is handled consistently in custom rasters; CI tests
Linux + Windows MSVC native on every PR and macOS arm64 on
release-tagged builds. The known gaps are documented as such
rather than hidden.

### Findings

- **X-MOD-1: Intel-Mac builds fail hard at CMake configure**
  (`cmake/OnnxRuntime.cmake:28-41`). When `CMAKE_SYSTEM_NAME ==
  "Darwin"` and the processor is not `arm64`, the build emits
  `FATAL_ERROR "ONNX Runtime tarball for macOS x86_64 is not
  published upstream"`. This is intentional and explicitly
  documented in `docs/packaging-macos.md` and the
  `release.yml`-comment block at line 242 (Intel-Mac users build
  from source). *Severity: Moderate (if Intel-Mac is in scope) /
  Confirmed-by-design (the FATAL_ERROR makes the gate loud).*
  No code change needed; surfacing this here so the maintainer's
  in-scope memory note (`project_intel_mac.md`) is reconciled with
  the build-time reality.

- **X-MIN-1: Mixed-DPR multi-monitor not handled.** Already
  tracked in `TODO.md ## Cross-cutting`. Thumbnail cache doesn't
  refresh on screen change between 1× and 2× displays. *Severity:
  Minor — edge case.*

### Confirmed-good positives

- **`AppPaths` covers all three platforms**
  (`src/settings/AppPaths.cpp:34-51`). macOS uses
  `~/Library/Application Support/Trailer`; Windows uses
  `QStandardPaths::AppDataLocation`; Linux uses XDG. No hardcoded
  `/Users/`, `~/Library/`, `C:\`, or `%APPDATA%` strings anywhere
  in `src/`.
- **`Share.mm` / `Share_stub.cpp` pattern enforced.** macOS-only
  Cocoa code lives in `.mm`; stub returns
  `ShareService::isAvailable() == false` on Linux / Windows; menu
  wired to that. No callsite assumes availability.
- **No `Q_OS_*` checks on architecture in source.** The
  `arm64|aarch64` vs `x86_64|x64` split is in CMake only.
- **CI matrix runs all three platforms.** Linux + Windows MSVC on
  every PR (`ci.yml`); macOS arm64 on release-tagged builds
  (`release.yml`). Windows MSVC and Windows mingw-w64 cross-compile
  are both tested — catches MSVC-only regressions that the
  mingw-w64 cross-build misses.
- **`QT_QPA_FONTDIR` set in Windows CI only.** Linux + macOS pick
  up system fonts via offscreen Qt; Windows needs the explicit
  pointer (`ci.yml:156`, `tests/uat/CMakeLists.txt`).
- **HiDPI / DPR handling consistent.** `ThumbnailModel.cpp:151-159`
  is the canonical pattern (multiply by DPR, render at native px,
  stamp `setDevicePixelRatio` on the result); `Magnifier`,
  `Screenshot`, `SignatureCanvas` all DPR-correct.

## 3. Accessibility

**Headline.** *Keyboard-navigable, modal-safe — not yet
screen-reader ready.* DESIGN.md §11.5 says screen-reader audit is
Planned, and the audit confirms that's accurate: **zero
`setAccessibleName` or `setAccessibleDescription` calls exist in
`src/`.** The keyboard side is in much better shape — every
documented shortcut is bound, tab order works, Esc paths exist,
arrow-keys nudge selected annotations.

### Findings

- **A-CRIT-1: No accessible names anywhere.** Zero
  `setAccessibleName()` or `setAccessibleDescription()` calls in
  `src/`. Every icon-only `QToolButton` and `QAction` will read as
  "button" under a screen reader. The label text on `QAction`s
  (`tr("Rectangle")`, `tr("Highlight")`, etc.) is present and
  could be reused as the accessible name; the wiring just hasn't
  been added. *Severity: Critical (blocker for screen-reader
  users) — but already acknowledged as Planned in DESIGN.md
  §11.5.*

- **A-MOD-1: Annotation tool shortcuts unbound.** Markup toolbar
  tools (Rectangle, Ellipse, Text, Highlight, etc.) have no
  individual `setShortcut` calls; only the toolbar toggle
  (`Ctrl+Shift+A`) is bound. A keyboard-only user has to toggle
  the toolbar then Tab through it. DESIGN.md §7 doesn't list these
  shortcuts, but standard convention (R for Rectangle, T for Text,
  H for Highlight) is plausible. *Severity: Moderate — workflow
  friction for keyboard-only users.*

- **A-MOD-2: Colour swatches communicate state by colour only.**
  `MarkupToolbar.cpp:88-105` and `Inspector.cpp:121-138` render the
  current stroke / fill colour as a pixmap swatch. The button has
  text ("Stroke") via `setText()` and a tooltip, but the *current
  colour* is conveyed only by the swatch's fill. *Severity:
  Moderate — function clear, state opaque.*

- **A-MIN-1: SearchBar icon-only buttons rely on tooltips only**
  (`SearchBar.cpp:30-43`). Tooltips aren't reliably read by all
  screen readers and require hover. `setAccessibleName` would
  upgrade them. *Severity: Minor.*

- **A-MIN-2: Sidebar mode picker's accessible name doesn't reflect
  current mode** (`MainWindow.cpp:426-458`). The button reads
  "Sidebar" regardless of whether the current mode is Thumbnails,
  Search Results, etc. *Severity: Minor.*

- **A-MIN-3: Signature canvas is mouse / stylus only**
  (`SignatureCaptureDialog.cpp:25-100`). No `keyPressEvent` — a
  keyboard-only user can't draw a signature, only import one.
  Inherent to drawing gestures; the file-import alternative
  exists and is sufficient. *Severity: Minor.*

### Confirmed-good positives

- **`FormOverlay` tab order correct.** `setTabOrder()` wired
  on the field chain sorted by visual reading order
  (`FormOverlay.cpp:66-90`).
- **`Inspector` tab navigation works out of the box** —
  `QFormLayout` + `QTabWidget` maintain a natural focus chain.
- **`AnnotationOverlay` keyboard nudging** — selected annotations
  respond to arrow keys (`Shift+arrow` for larger steps),
  `Delete`/`Backspace` to remove (`AnnotationOverlay.cpp:1084-1129`).
  Drag is the visual affordance; keys are the keyboard equivalent.
- **Sidebar mode is reachable via menu**
  (`MainWindow.cpp:436-456`). Alt+V → Sidebar → mode submenu.
- **All modal dialogs are Esc-cancellable.** `QDialogButtonBox`
  with `Cancel` connected to `reject()`; Qt fires that on Esc.
- **`MainWindow::keyPressEvent` dismisses Magnifier + SearchBar
  on Esc** (`MainWindow.cpp:2585`, `SearchBar.cpp:80`).
- **Drag-and-drop has menu equivalents.** `File > Open`
  (`Ctrl/⌘+O`) covers the drag-open case.
- **No hardcoded UI font sizes.** `setPointSize()` calls are all
  for annotation rendering (document content), not UI chrome —
  the app respects OS font preferences.
- **DESIGN.md §7 shortcut table reconciled.** Every documented
  shortcut is bound; the four `Planned` rebindings landed earlier
  on this branch (`3720d0b`).

## 4. Failure-mode / robustness

**Headline.** *Defensive and well-structured.* No crashes on
plausible bad input were found. Exception handling from external
libraries (qpdf, ONNX Runtime, Qt JSON / TOML) is consistent;
errors surface to the user via `flashError()` in hot paths; the
app degrades gracefully on missing or corrupt settings, recent
files, models, and dictionaries. Popups appear only where
PHILOSOPHY's rule allows them (irreversible actions, one-time
consent).

### Findings

- **F-MOD-1: `QPdfDocument::load` error on snapshot path is
  silent at the inner call** (`PdfEditor.cpp:910-911`). The
  inner function returns `false` and the outer caller (`PdfAdapter`)
  surfaces via `flashError()`, but the inner-function contract
  doesn't itself signal *why*. *Severity: Moderate — error path
  works, but the message could lose specificity.*

- **F-MOD-2: OCR dictionary load failure is silent**
  (`OcrEngine.cpp:343-369`). If `Q_INIT_RESOURCE` fails or the
  `:/ml/ppocr_en_dict.txt` qrc entry is missing at link time,
  `qWarning` logs and OCR returns an empty result with no UI
  signal. *Severity: Moderate — build-time bug, not runtime, but
  would manifest as "OCR silently does nothing" if it ever
  shipped.*

- **F-MIN-1: `Q_UNREACHABLE` in ModelId switch**
  (`ModelRegistry.cpp:43`). Reachable only via code bug in the
  caller (enum-controlled input); `Q_ASSERT_X` or a soft error
  return would degrade more gracefully. *Severity: Minor — low
  likelihood.*

- **F-MIN-2: Foreign annotation `/Subtype`s silently dropped on
  save** (`PdfEditor.cpp:1107-1111`). Annotations Trailer doesn't
  understand (e.g. `/PrinterMark`, `/Redact`) are skipped on
  write. *Severity: Minor — by design per PHILOSOPHY ("the kinds
  of files non-technical people send each other"), but worth
  knowing.*

### Confirmed-good positives

- **`ORT::Session` init failure caught**
  (`OnnxSession.cpp:106-112`). `Ort::Exception` → `qWarning` →
  null return; callers check.
- **Corrupt `recent.json` handled.** Empty list, app launches
  fine (`RecentFiles.cpp:26-40`).
- **Corrupt `settings.toml` handled.** Defaults apply, app
  launches fine (`Settings.cpp:88-92`).
- **`QImageReader` results checked.**
  `SignatureCaptureDialog.cpp:295` checks `img.isNull()`.
- **`QFutureWatcher::result()` after worker exception returns a
  default value.** `MainWindow::onRemoveBackground:1324-1333`
  treats `isNull()` as the error case; correctly falls through.
- **Password-protect popups are correct PHILOSOPHY use.** The
  `MainWindow:1935-1941` warnings ("Password mismatch", "Empty
  password") gate an irreversible (encryption) action — exactly
  the case where popups are allowed.
- **No raw `new`/`delete` leakage found in `src/document/`,
  `src/ml/`, `src/ui/AnnotationOverlay.cpp`.** RAII discipline
  consistent; `QPointer` used per CONVENTIONS §5.

## 5. i18n / Unicode coverage

**Headline.** *Functionally translation-ready; organisationally not.*
471 `tr()` calls across ~92 source files — the discipline of wrapping
user-visible strings is in place. But there is no CMake translation
scaffold (no `qt_add_translation` call, no `trailer_*.ts` files), and
several string-construction patterns will cause translator friction
when Phase 8 starts.

### Findings

- **I18N-CRIT-1: No translation framework scaffold.** Zero
  `qt_add_translation` / `lupdate` / `lrelease` CMake calls and zero
  `trailer_*.ts` files in the tree. Phase 8's *Localisation framework
  + at least English* starts from cold. *Severity: Critical — but
  expected; DESIGN.md §10 Phase 8 explicitly marks this Planned.*

- **I18N-MOD-1: Multipart string construction loses translator
  context.** `MainWindow.cpp:1982-1990` builds a status message
  across three `tr()` calls plus literals; `MainWindow.cpp:416` and
  `Sidebar.cpp:447` bake `"p"` / `"p."` as a page-number prefix
  inside a `tr()` format string — translators can't replace the
  prefix with a locale-specific abbreviation. *Severity: Moderate.*

- **I18N-MOD-2: ISO date format in user-visible tooltips.**
  `SignaturePicker.cpp:62` and `SignaturesDialog.cpp:66` render
  signature timestamps via `Qt::ISODate`, bypassing locale.
  Should be `QLocale().toString(date)`. *Severity: Moderate.*

- **I18N-MOD-3: Plural handling incomplete.**
  `OcrResultsDialog.cpp:31` is the only correct `%n` use in the
  tree. `MainWindow.cpp:2372-2382` branches on conditionals
  ("filled 0 of N", "filled 1 of N", "filled M of N") rather than
  using one `%n`-templated string with locale-specific plural
  forms. French, Russian, Arabic, Polish all have non-English
  plural rules. *Severity: Moderate.*

- **I18N-MOD-4: No translator-context comments.** Short ambiguous
  strings (`tr("Ready")`, `tr("Clean")`, `tr("—")`) lack `//:`
  comments. Translators won't know whether *Ready* means "model
  ready to use" or "UI ready". *Severity: Moderate — translator
  friction at .ts-file generation.*

- **I18N-MOD-5: Locale-agnostic number rendering.**
  `Inspector.cpp:398` and `ThumbnailModel.cpp:142` use bare
  `QString::number(...)` instead of `QLocale().toString(...)`.
  *Severity: Moderate — cosmetic for Latin/Cyrillic, noticeable in
  RTL.*

- **I18N-MIN-1: RTL layout untested.** No explicit
  `setLayoutDirection(Qt::RightToLeft)` calls, and no offscreen
  test that flips the layout. Qt auto-mirrors many things, but the
  custom annotation overlay and sidebar layouts haven't been
  verified. *Severity: Minor — pre-shipping concern, not current
  bug.*

- **I18N-MIN-2: Hardcoded em-dashes / "N/A" markers.**
  `Inspector.cpp:398,403,422` and `MainWindow.cpp:1988` embed
  `"—"` or `"—"` inside or alongside `tr()` calls. Translators
  can't switch to locale-appropriate "N/A" forms. *Severity:
  Minor.*

### Confirmed-good positives

- **`tr()` coverage is extensive.** 471 calls across the tree
  means almost every user-visible string is already marked for
  translation. The wrapping discipline is in place; Phase 8 starts
  from a good baseline.
- **`QObject::tr()` used correctly in free functions / lambdas.**
  46 explicit `QObject::tr` calls outside QObject subclasses —
  the right pattern for translation-context preservation.
- **Locale-aware `formattedDataSize` for file sizes.**
  `MainWindow.cpp:1984-1985` — German dots-for-thousands and
  French spaces are respected.
- **Correct `%n` plural in OCR dialog.**
  `OcrResultsDialog.cpp:31` is the template every other count-
  sensitive string should follow.

## 6. Test coverage gaps

**Headline.** *Strong anchor cases, predictable gaps.* `PdfEditor`
has a 1323-line test file with 35 slots; `AnnotationStore` has a
185-line file with 9 covering the core mutation contract. Around
those two pillars, coverage thins predictably: UI widgets have no
unit tests (caught by UAT instead), several core classes test the
happy path but not boundary / degradation cases, and one class
(`ModelDownloader`) has no test file at all.

### Findings

- **TEST-CRIT-1: `kMaxUndo = 64` overflow not tested.**
  `test_annotation_store.cpp` covers add/remove/update/undo/redo/
  signals across 9 slots, but no mutation pushes past 64 snapshots
  to verify the cap fires. A refactor that breaks the
  `m_undoStack.size() > kMaxUndo` guard wouldn't be caught.
  *Severity: Critical — boundary-condition gap on a documented
  memory-integrity contract (CONVENTIONS §3).*

- **TEST-MOD-1: `PdfCommand` symmetry pattern not generalised.**
  `test_pdf_editor.cpp:704-749` tests rotate's apply→revert→apply
  idempotence — but for the one command that exists. When delete /
  move / insert / crop land (currently on the in-flight branch),
  there's no reusable harness to enforce the same symmetry
  contract. *Severity: Moderate — pattern fragility under
  expansion.*

- **TEST-MOD-2: `Settings` corrupt-file degradation untested.**
  The robustness audit (§4) confirmed `Settings.cpp:88-92` falls
  back to defaults on `toml::parse_error`. `test_settings.cpp`
  covers defaults / round-trip / missing file but not a
  deliberately-malformed file. The behaviour is correct; the
  guard isn't pinned by a test. *Severity: Moderate.*

- **TEST-MOD-3: `RecentFiles` legacy-format migration untested.**
  `test_recent.cpp` covers the current format end-to-end; no
  test loads a hand-written pre-branch JSON to verify the
  `hasViewState()` sentinel fall-through. *Severity: Moderate —
  upgrade-scenario fragility.*

- **TEST-MOD-4: `SignatureStore` same-millisecond collision
  untested.** `SignatureStore.cpp:79`'s `m_seq` counter exists
  specifically to guarantee collision-free naming when two saves
  fall in the same millisecond; `test_signatures.cpp:72` spaces
  saves by 5 ms. A refactor that drops `m_seq` would still pass.
  *Severity: Moderate.*

- **TEST-MOD-5: `ModelDownloader` has no test file.** Network
  logic, SHA-256 verification, temp-to-final write, cancel
  semantics — all only exercised indirectly via integration tests
  that mock the downloader out. The privacy audit (§1) confirmed
  the implementation is sound; a regression would surface in
  HITL dogfooding (models fail to download) but the gap is
  notable. *Severity: Moderate.*

- **TEST-MOD-6: `CardStore` `replaceCard` + active-index
  interaction untested.** `test_cards.cpp` covers the matcher
  thoroughly (222 lines) and the `removeCard` clamp, but
  `replaceCard` and the add/remove ↔ active-index dance are not
  exercised. *Severity: Moderate.*

- **TEST-MIN-1: `AnnotationOverlay` (~1200 lines) is
  integration-tested only.** Hit-testing, coordinate-callback
  transforms, text-selection logic — all complex, all only
  exercised via `test_adapters.cpp` and UAT. Unit-testing would
  catch edge cases (floating-point rounding, viewport
  boundaries) but UAT covers the user-visible behaviour. The
  CONVENTIONS §4 doc is the protective layer here. *Severity:
  Minor.*

- **TEST-MIN-2: `Magnifier`, `Inspector` have no unit tests.**
  Pure UI widgets; breakage visible immediately during
  dogfooding. *Severity: Minor.*

### Confirmed-good positives

- **`PdfEditor` test is the project's anchor.** 1323 lines, 35
  slots, covers rotation, redaction, page operations, form
  fields, encryption. The symmetry contract for
  `RotatePageCommand` is explicitly tested (apply→revert→apply).
- **`AnnotationStore` core mutation contract has nine focused
  slots.** add / remove / update / undo / redo / signal emission
  all covered; the boundary is the one gap.
- **`test_signatures.cpp` is thorough for file-layout +
  PNG-synthesis.** Orphan PNG handling, JSON sidecar, monotonic
  naming all verified — just not the ms-collision edge.
- **The two highest-stakes classes (PdfEditor, AnnotationStore)
  are also the most-tested.** The project's test discipline
  shows in where it concentrated effort.

## 7. License / attribution

**Headline.** *License claims are accurate, attribution shipping is
the gap.* PHILOSOPHY / README / DESIGN / LICENSE all agree
(MIT). `THIRD_PARTY_LICENSES.md` is well-structured (Qt 6, ONNX
Runtime 1.25.0, qpdf, toml++, PaddleOCR dict, model weights). The
model-weights-on-demand strategy correctly defers their license
obligations to the user's local cache. But the *install rules* in
CMakeLists.txt don't ship the upstream LICENSE / NOTICE files
that Apache-2.0 attribution requires.

### Findings

- **LIC-CRIT-1: Third-party LICENSE files not installed
  alongside the binary.** `THIRD_PARTY_LICENSES.md` enumerates
  the deps, but `CMakeLists.txt` has no install rule copying
  qpdf's Apache-2.0 LICENSE, ONNX Runtime's MIT LICENSE, or the
  PaddleOCR dictionary's Apache-2.0 NOTICE into the distribution
  package. Apache-2.0 §4.1 requires attribution alongside the
  binary; shipping a binary without those LICENSE files is a
  legal exposure for downstream packagers. *Severity: Critical
  for first release; not yet a problem because there's no
  signed release yet.*

- **LIC-MOD-1: BiRefNet model registered but undocumented.**
  `ModelRegistry.cpp:86-93` registers `ModelId::BiRefNetLite`
  pointing at `github.com/ZhengPeng7/BiRefNet` (MIT-licensed).
  `THIRD_PARTY_LICENSES.md` §2 enumerates U²-Net / MobileSAM /
  PP-OCRv3 / PP-OCRv4 but not BiRefNet. The download URL +
  SHA-256 are not yet pinned (still placeholders), so the
  attribution gap doesn't ship today — but the doc must catch
  up before the URL lands. *Severity: Moderate — preventable if
  caught now.*

- **LIC-MOD-2: Qt 6 LGPLv3 obligation not surfaced in
  README / DESIGN.** Both files say "Trailer is MIT" without
  noting that the *binary* inherits Qt's LGPLv3 obligations
  (dynamic linking + relinking allowance + LGPL text
  redistribution). `THIRD_PARTY_LICENSES.md` covers this
  correctly, but the top-level README leaves a casual reader
  with the impression that the binary is MIT-only. *Severity:
  Moderate — accurate technical writing; reader inference.*

- **LIC-MOD-3: About dialog lists no credits.**
  `MainWindow::onAbout()` shows version + phase only. Desktop
  convention is *Help → About → Credits* with a scrollable
  list of deps + their licenses. Even a one-line link to
  THIRD_PARTY_LICENSES.md inside the About box would close the
  in-app discovery gap. *Severity: Moderate.*

- **LIC-MIN-1: Windows installer (`platform/windows/trailer.wxs`)
  doesn't reference THIRD_PARTY_LICENSES.md.** The `.wxs` has
  TODO comments for licence agreement dialog, Authenticode
  signing, and real URLs — all expected; the licence-shipping
  shape just needs to be added when that work lands. *Severity:
  Minor.*

### Confirmed-good positives

- **Models downloaded on demand, not bundled.** `ModelRegistry`
  defers Apache-2.0 redistribution obligations to the user's
  local cache by design (PHILOSOPHY: explicit consent before
  network). This is a *win* for legal-readiness — the project
  avoids most of the model-weights attribution surface
  altogether.
- **No GPL / AGPL entanglement.** Poppler was rejected in
  favour of Qt PDF specifically for this reason; the audit
  found no other GPL surface in `src/` or `cmake/`.
- **`Share.mm` uses OS-frameworks only.** macOS NSSharingService
  is part of the OS — no separate redistribution / licence
  surface.
- **LICENSE file at repo root is standard MIT.** Plain text,
  unambiguous, copyright "Trailer contributors" 2026.
- **THIRD_PARTY_LICENSES.md is well-structured.** Two sections
  (linked / bundled, then download-on-first-use) with a per-dep
  table including upstream URL, version, and licence text. The
  "Updating this file" footer reminds contributors to keep it
  current when bumping pinned versions.

## 8. Code complexity / maintainability hotspots

**Headline.** *Three structural pain points concentrated around
annotation handling.* The codebase's testing discipline and ML
factoring are solid, but adding a new annotation type today is a
multi-file change with no compile-time guarantee that every site
was updated. The MainWindow god-function is the second-known
issue. The flat 35-slot `test_pdf_editor.cpp` will become an
adoption barrier as more PdfCommand subclasses land.

### Findings

- **CPLX-CRIT-1: `AnnotationType` switch scattered across five
  files.** `Sidebar.cpp` (30 cases), `Inspector.cpp` (30),
  `PdfEditor.cpp` (15), `AnnotationOverlay.cpp` (15),

## 9. API surface stability for 1.0

**Headline.** *Most surfaces feel stable; the documentation that
locks them down doesn't exist yet.* The persisted enums
(`AnnotationType`, `ModelId`) are immutable once shipped (they
map to PDF `/Subtype` strings and to model filenames on disk),
but neither has a "do not renumber" comment to protect them
from a future contributor. PHILOSOPHY commits to backwards-
compat at 1.0 but the *enumeration* of frozen surfaces lives in
nobody's head yet.

### Findings (ordered as freeze-priority)

- **API-CRIT-1: `AnnotationType` enum must never be renumbered
  or have values removed.** Each value maps to a PDF `/Subtype`
  string in `PdfEditor.cpp`'s `readAnnotations` /
  `writeAnnotations`. A renumber breaks every PDF Trailer has
  ever saved. The enum has no comment warning of this. *Severity:
  Critical — protective doc gap.*

- **API-CRIT-2: `ModelId` enum must never be renumbered.** Each
  value pins an on-disk model filename via `ModelRegistry::modelIdKey`.
  Renumber and Trailer looks in the wrong directory for cached
  models, or treats a different model's policy flag as the new
  model's. No protective comment. *Severity: Critical —
  protective doc gap.*

- **API-MOD-1: `IDocument` interface is "still flexing."** ~50
  virtual methods; most have no-op defaults. No documented
  distinction between "called by UI (public contract)" and
  "called only by adapters (internal)." A 1.1 minor bump that
  changes a method signature would break out-of-tree adapters
  the project might never see. Recipe is in CONVENTIONS §1 but
  there's no stability commitment doc. *Severity: Moderate.*

- **API-MOD-2: `PdfCommand` symmetry contract has no migration
  guide.** CONVENTIONS §2 documents the rule (`apply → revert →
  apply == apply`) but doesn't address "what does a future
  breaking change to this contract look like?" Once the
  delete/move/insert/crop commands on the in-flight branch land,
  reverting that contract is hard. *Severity: Moderate.*

- **API-MOD-3: No `SETTINGS.md` documenting the on-disk
  schemas.** `settings.toml`, `recent.json`, `cards.toml`, and
  the signature folder layout are all defensively-coded
  (additive fields, sentinel defaults, legacy compat reads) —
  but the *rules* aren't written down anywhere. A future
  contributor renaming a key wouldn't know they were violating
  a 1.0 commitment. *Severity: Moderate.*

- **API-MOD-4: PDF annotation `/Subtype` round-trip policy is
  undocumented.** Trailer round-trips ten `/Subtype`s and
  silently drops the rest (F-MIN-2 in the failure-mode audit —
  "by design"). The "what's dropped" list isn't in
  DESIGN.md §6.3, PHILOSOPHY, or CONVENTIONS — only in the
  source. *Severity: Moderate.*

- **API-MOD-5: Keyboard shortcuts are user-facing API.** Once
  shipped, muscle memory makes them a commitment. The DESIGN.md
  §7 table is the spec now; what isn't spelled out is the
  *commitment* — that 1.0+ shortcuts won't change defaults
  across minor bumps. *Severity: Moderate — commitment-doc gap.*

- **API-MIN-1: CLI surface (`trailer file1.pdf file2.png`) has
  no doc.** Positional args only, no flags. Stable as-is, but a
  one-page `docs/cli.md` would lock it down. *Severity: Minor.*

- **API-MIN-2: `Sidebar::Mode`, `ViewMode`, `Theme`,
  `OpenFilesIn` enums lack "never renumber/remove" comments.**
  Less critical than `AnnotationType` and `ModelId` (these are
  more session-state than on-disk-format), but the same shape
  of protective comment is appropriate. *Severity: Minor.*

### Recommended action sequence for 1.0

1. **Annotate persisted enums in-place.** Add `// API: do not
   renumber or remove values — persisted via *X*. See
   docs/api-stability.md.` next to `AnnotationType`, `ModelId`.
   Smaller annotations on `Sidebar::Mode`, `ViewMode`, `Theme`,
   `OpenFilesIn`.
2. **Write `docs/api-stability.md`** enumerating every public
   surface, its stability classification (Frozen / Additive-only
   / Internal-but-exposed / Still-flexing), and the per-surface
   migration rules.
3. **Write `docs/settings.md`** documenting all on-disk schemas
   (`settings.toml`, `recent.json`, `cards.toml`, signature
   folder, qrc resource layout) with their additive-only rules.
4. **Annotate `IDocument`** with which methods are public-
   contract vs adapter-internal.
5. **Add a "what gets dropped on save" section to DESIGN.md**
   covering the PDF `/Subtype` policy.

## 10. Security beyond the network surface

**Headline.** *No RCE, no arbitrary file write, no privilege
escalation — but a malicious file can DOS the process via
resource exhaustion.* Path-handling, symlink discipline, temp
files, and process invocation all audit clean. The four
moderate findings are all of one shape: an attacker-controlled
size field (annotation `/Contents`, image pixel dimensions,
clipboard image, form field value) gets read into memory without
a pre-flight cap.

### Findings

- **SEC-MOD-1: Annotation `/Contents` read without size cap**
  (`PdfEditor.cpp:1124-1127`). `getUTF8Value()` materialises the
  full string. A PDF with a 1 GB `/Contents` field OOMs the
  process during parsing. *Severity: Moderate — DOS via
  attacker-supplied file.*

- **SEC-MOD-2: Image decode unbounded** (`ImageAdapter.cpp:232-242`).
  `QImageReader::read()` is called with no size pre-check. A
  PNG header claiming 100 000 × 100 000 pixels causes Qt to try
  to allocate ~40 GB. Qt throws, but the user's system has
  already been DOS'd during the attempt. *Severity: Moderate.*

- **SEC-MOD-3: Clipboard image unbounded**
  (`Application.cpp:255-262`). `clipboard()->image()` returns
  whatever's on the pasteboard; a hostile process could place a
  pathologically-large image. *Severity: Moderate.*

- **SEC-MOD-4: Form field value unbounded**
  (`PdfEditor.cpp:1297`). `field.getValueAsString()` returns
  the raw string; a malicious form with a multi-gigabyte field
  OOMs. *Severity: Moderate.*

- **SEC-MIN-1: Drag-and-drop type inference is extension-based**
  (`MainWindow.cpp:2523-2534`). A `.png` that's actually
  something else gets routed to `ImageAdapter::open()` and then
  to `QImageReader`. Qt's codecs are well-hardened; the risk is
  low in practice. *Severity: Minor.*

- **SEC-MIN-2: Signature import passes EXIF through.**
  `SignatureCaptureDialog` doesn't scrub EXIF from imported
  signature PNG/JPEG. A user importing a phone photo may
  accidentally embed GPS coordinates / camera info in the
  signature file. *Severity: Minor — user-expectation issue,
  not a code defect.*

- **SEC-MIN-3: Password `QString` not explicitly zeroed.**
  Standard Qt practice; passwords linger in the string pool
  until GC. Acceptable for the local-only threat model.
  *Severity: Minor.*

### Confirmed-good positives

- **Path traversal blocked everywhere.** All `AppPaths` joins
  use `QDir::cleanPath`; `SignatureStore` filters with
  `QDir::NoSymLinks`.
- **PDF parse exceptions caught.** `PdfEditor.cpp:33-57`
  handles qpdf throwing on malformed input; the unlock path
  distinguishes `QPDFExc` from generic `std::exception`.
- **Symlink-safe save.** `PdfAdapter.cpp:975-976` uses
  `canonicalFilePath()` to detect when source and target
  resolve to the same inode.
- **Temp files are RAII.** `ScopedTempFile` +
  `makeUniqueTempPath` sidestep the Windows
  `FILE_SHARE_DELETE` race.
- **`QProcess` shells out to one hardcoded path
  (`/usr/sbin/screencapture`).** No variable interpolation, no
  shell invocation.
- **Settings.toml is injection-safe.** No path / URL / shell-
  command fields; only enum strings and safe values.
- **Logs don't leak content.** `qWarning` / `qCritical` calls
  emit only model names + error codes; no paths, no document
  content.
- **Recent files canonicalised.** Deduplication by canonical
  path prevents symlink confusion.

### Threat-model framing

The findings above are all *DOS-via-malicious-input* — a file
crafted by an attacker, sent to a user via email / AirDrop /
Messages (Trailer's stated threat model in DESIGN.md), can
cause the Trailer process to consume excessive memory. The
attacker gains nothing beyond inconveniencing the user;
nothing is written to disk, no other files are read, no
network call results, no shell command runs. **Defending
against these would mean pre-flight size validation in the
four read paths above** — straightforward but doesn't ship
today.

## 11. Error message quality and observability

**Headline.** *Foreground error UX is good; background observability
is genuinely thin.* `flashError` is used consistently in
hot paths; popups are reserved for irreversible actions per
PHILOSOPHY; the "no popup that says no" rule is honoured. But
silent ML inference failures, raw `errorString()`-style system
messages, and the complete absence of file logging mean a
field bug arrives as "it just didn't work" with no log to
attach.

### Findings

- **ERR-MOD-1: ML inference failures are user-silent**
  (`BackgroundRemover::remove`, `OcrEngine::recognize`,
  `OnnxSession::create`). On failure these return null /
  empty; the caller treats that as "no result." Per
  PHILOSOPHY this is correct for "I tried and didn't help" —
  but the user can't tell whether the model didn't run vs
  ran-and-found-nothing. *Severity: Moderate — discoverability
  vs PHILOSOPHY tension.*

- **ERR-MOD-2: File-operation errors surface a path but no
  `errorString()`** (`MainWindow.cpp:1614, 1784, 1815, 1820,
  1974` etc.). A user seeing "Save failed — could not write to
  /path" can't tell if it's permissions, disk-full, or file-
  locked. *Severity: Moderate.*

- **ERR-MOD-3: OCR dictionary load failure is fully silent**
  (`OcrEngine.cpp:481-482`). Already F-MOD-2 in the
  failure-mode audit. Re-confirmed. *Severity: Moderate.*

- **ERR-MOD-4: Model-download failure shows raw network errno
  text** (`ModelManagerDialog.cpp:186-189`). "Could not fetch
  Background Remover: Connection reset by peer" — verbatim,
  no remediation hint, no "check network and retry" framing.
  *Severity: Moderate.*

- **ERR-MIN-1: No crash diagnostics.** `AppPaths::logsDir()`
  exists but no shipped code writes to it. No
  `qInstallMessageHandler` to file. No "Trailer crashed last
  time" recovery dialog on next launch. *Severity: Minor —
  field-bug-report blindness.*

- **ERR-MIN-2: Export pre-write validation gap**
  (`MainWindow.cpp:1605-1615`). After `QFileDialog` returns a
  path, no `QFileInfo(path).isWritable()` check before the
  long export operation. Failure is detected late. *Severity:
  Minor.*

- **ERR-MIN-3: Background-removal silent on bad-quality
  result.** No "preview before commit" path; a low-quality
  mask is applied with no caveat. User can undo, but no
  signal that the result is below threshold. *Severity:
  Minor.*

### Confirmed-good positives

- **`flashError` messages are typically specific and
  actionable.** "Crop failed — margins may be too large"
  suggests the fix; "Insert failed — could not insert pages
  from [path]" names the failing input.
- **`tr()` wrapping is comprehensive on error path.** Every
  user-visible error string the audit found goes through `tr()`.
- **Password warnings are exemplary PHILOSOPHY use.** "Password
  mismatch", "Empty password" gate an irreversible (encryption)
  action — correct popup use.
- **`Share` menu silently hidden on non-macOS is correct.**
  Per PHILOSOPHY's "no popup that says no" rule, hiding the
  unavailable menu is right; the alternative
  (greyed-with-tooltip) would advertise a feature the user
  can't actually have.
- **`MainWindow::onAbout()` doesn't leak.** Version + phase
  only; no system info, no IDs.

### What's missing for field-readiness

A future "Trailer crashed last week and a user filed a vague
issue" workflow has zero artifact today:
- No log file at `AppPaths::logsDir()/trailer_<date>.log`.
- No qInstallMessageHandler routing.
- No core-dump configuration hint.
- No bug-report helper that bundles the local log + version
  info into one paste-able blob.

Wiring `qInstallMessageHandler` to append to
`AppPaths::logsDir()` + a rolling-7-days retention would close
~80% of this gap with maybe 50 lines of code. The PHILOSOPHY
no-telemetry rule explicitly permits local logging; the
constraint is *never phone home*, not *never write logs*.

## 12. Concurrency / thread races (post-merge)

**Headline.** *Strong discipline; no critical races found.* The
new `MlScheduler` worker thread + `CancellationToken` acquire/
release atomics + raw-pointer flush via
`DocumentView::documentAboutToBeRemoved` form a coherent
concurrency design. The audit walked five plausible adversarial
scenarios (rapid tab-switch mid-OCR, AC unplug mid-SAM-encode,
close-mid-Remove-Background, Instant Alpha → Smart Lasso swap,
worker exception) and found no use-after-free, deadlock, or
ordering bug.

### Findings

- **CONC-MOD-1: Multi-cache flush in
  `MainWindow::documentAboutToBeRemoved` handler is synchronous
  but reentrancy-sensitive.** The handler synchronously flushes
  `m_backgroundCandidateDocs`, `m_pendingCandidateJobs`,
  `m_autoEnabledFormDocs`, `m_restoredViewStateDocs`, then calls
  `SamController::purgeDocument` and `OcrController::setDocument(nullptr)`.
  If any of those calls (in particular
  `OcrController::setDocument`) ever queues a new ML task as a
  side-effect of a signal cascade, that task could race with the
  in-progress cancellation. No such cascade exists today; calling
  this out so it stays caught if one ever creeps in. *Severity:
  Moderate — protective gap, no current violation.*

- **CONC-MOD-2: `OcrController` raw-`IDocument*` key stability
  depends on signal-connection order.** `setDocument(nullptr)`
  must execute before the doc's `unique_ptr` erases, which it
  does today because `documentAboutToBeRemoved` is emitted
  synchronously before erase. A future re-ordering of the
  emission point or a future listener that handles the signal
  via `Qt::QueuedConnection` would break this. *Severity:
  Moderate — fragile to refactor.*

- **CONC-MIN-1: `BackgroundCandidateScorer` result callback uses
  raw `doc` pointer with allocator-reuse window.** The lambda's
  doc pointer is compared against `currentDocument()` on GUI
  thread, but a recycled allocator address could in principle
  pass the equality check after a close-then-immediate-reopen at
  the same heap location. The synchronous flush in
  `documentAboutToBeRemoved` makes the window microscopic;
  surfacing as theoretical rather than observed. *Severity:
  Minor.*

### Confirmed-safe positives

- **`CancellationToken::cancel()` uses `memory_order_release`;
  `isCancelled()` uses `memory_order_acquire`.** Correct
  ordering — workers can't see stale "not cancelled" after the
  GUI thread has cancelled.
- **`MlScheduler::m_nextId.fetch_add` with `memory_order_relaxed`** —
  appropriate, since ID uniqueness doesn't synchronise with
  task execution.
- **`DocumentView::documentAboutToBeRemoved` emission order:**
  `removeTab() → emit → erase`. Raw `IDocument*` deref in
  listeners is valid; the pointer is dead only after the last
  listener returns.
- **SAM encoder LRU + worker shared_ptr<SamSession>:** worker
  lambdas capture by value; the session outlives the controller
  destruction. No double-delete.
- **`OcrController::setDocument(nullptr)` cancels in-flight
  tasks**; `QPointer<SelectableTextStore>` guards drop late
  results.
- **MlScheduler power-state poller** unlocks the mutex before
  calling `reevaluatePowerPolicy()`, then reacquires — the
  correct unlock-reevaluate-reacquire pattern. No deadlock.
- **`MlScheduler::stats()` snapshot** reads queue/running/
  priority/label under a single lock. Status-bar indicator
  sees an atomic view.
- **Worker exceptions** caught + `m_running` cleared + waiters
  notified. Exception-safe.

## What this audit still didn't cover

Eleven lenses surveyed across three rounds (privacy,
cross-platform, accessibility, failure-mode, i18n, test
coverage, license, complexity, API stability, security-beyond-
network, errors+observability). Lenses still open for a future
round:

- **Thread / concurrency races** beyond the QPointer-discipline
  spot-checks the failure-mode and security lenses already did.
  Most valuable after `MlScheduler` lands with the in-flight
  branch — the priority bands + cancellation token introduce
  new race surfaces.
- **Performance.** Cold-start time, PDF first-page render
  latency, continuous-scroll FPS on a 500-page PDF, OCR
  throughput. DESIGN.md §11.4 names these as targets; no
  baseline benchmark exists. Requires a working build env.
- **UX / first-30-seconds.** The `docs/smoke-session.md`
  protocol exists but hasn't actually been run on this
  branch; no findings to fold in yet. The synthesis at the
  start of this branch's work captured the *signal* from
  past HITL passes, but doesn't substitute for a real
  reference-user run.
- **Long-term architectural drift.** What does the codebase
  look like after three more in-flight-branch-sized merges?
  Where do the seams want to be? The complexity findings
  here are point-in-time; a forward-looking architectural
  audit would name the next obvious refactor that doesn't
  yet feel urgent.
