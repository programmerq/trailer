# HiDPI image-open 1:1 — before/after evidence

Fix: screenshots / clipboard grabs on a Retina (dpr=2) display now open
at their **logical** size and render **pixel-exact at Actual Size**,
instead of opening ~2x oversized and blurry.

| | image |
|---|---|
| **Before** (dpr stripped → fit-shrink then screen re-upscales → double resample) | `image-open-1to1-before-dpr2.png` |
| **After** (capture dpr stamped → Actual Size hands raw device px through 1:1) | `image-open-1to1-after-dpr2.png` |

Both PNGs are 1600×1000 — the *physical* pixels of an 800×500-pt area on
a 2× display. In the **before** image the 1px grid and hairline
diagonals are softened/muddied and the text edges are fuzzy: the capture
arrived as raw device pixels with `devicePixelRatio` stripped (the PNG
round-trip drops it), so the viewer fit-shrank it to the logical
viewport (scale 0.5) and the screen then re-interpolated it back up 2×
on paint. In the **after** image the same content is razor-sharp because
the capture's real dpr is stamped and "Actual Size" hands the raw device
pixels straight to the screen with no resample (1 source device px → 1
physical px).

## Honesty / caveats

- **dpr=2 here is SIMULATED.** The offscreen Qt platform used in CI
  reports `devicePixelRatio = 1`, so it cannot render a genuine Retina
  frame. These PNGs emulate the exact resample chain a 2× screen
  applies (down-to-logical then up-to-physical for *before*; identity
  for *after*). dpr is injected on a synthetic `QImage` via
  `setDevicePixelRatio()` — the same technique used by the unit tests
  (`tests/test_image_scale.cpp`) and by PR #70's thumbnail test.
- The **after** side reproduces production output: `applyScale(1.0)` /
  `buildDisplayPixmap(src, 1.0)` returns the source device pixels with
  the dpr stamp and no resampling — asserted directly by
  `test_image_scale::actualSizeIsPixelExact` (dpr ∈ {1, 1.5, 2}).
- A true end-to-end Retina render still wants **owner confirmation on a
  physical 2× Mac** before this is considered visually signed off.
